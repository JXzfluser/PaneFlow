# 2026-09-13

## 运行时间线（D11）——把「明厨亮灶」装进界面

**目标**：消费已经在盘上但前端零消费的 `run.events`（`/api/runs/:id/events` + WS 推的 RunRecord.events）。

**实现**
- 新增 `packages/web/src/timeline.ts`（纯逻辑，可脱离 DOM 单测）：`EVENT_META`/`TIMELINE_FILTERS`/`eventStats`/`filterEvents`/`fmtClock`/`relLabel`/`summarizeTimeline`/`lastEvent`。未知事件类型兜底到 `UNKNOWN_META`。
- 新增 `components/RunTimeline.tsx`：类别筛选条（带计数，0 条置灰）、`HH:MM:SS` + `+6m30s` 相对耗时、节点芯片（可点击 → 选中画布节点）、跟随最新 / 排序切换、运行中实时点 + 「当前在做什么」。
- 两个入口：**运行中心**运行卡片 `⏱ N` 展开（历史运行按需 `GET /events`，运行中直接吃 store 的 WS 数据）；**底部控制台**新增「时间线」标签（实时）。
- `api.ts` 加 `runEvents(runId)`；`shared/index.ts` 导出 `RunEvent` 类型。

**顺带修掉两个真 bug**（都是新增验证暴露的）
1. `graph-serialization.ts` 的 `graphToRfParts` 读 `graph.metadata.createdAt` 无兜底 → 任何缺 `metadata` 的 graph（API 客户端提交、旧版本落盘）点「在画布中打开」整页崩溃。改为 `graph.metadata?.`，补单测。
2. 画布只把选中态单向写进 store（`onNodeClick`），从不回显 → 时间线/步骤清单点节点芯片后画布无高亮。`Canvas.tsx` 新增 `rfNodes` 派生（不写回 store，避免污染自动保存）。

**验证**
- `pnpm test` = **122 全绿**（server 92 + web 30；新增 `timeline.test.ts` 17 条 + graph-serialization 1 条）。
- 浏览器 29 条断言全过（`pf-verify-timeline.mjs`，11 条事件 fixture 放 `/tmp/paneflow-verify/spaces/demo/runs/run-tl-001.json`）；截图 `/tmp/pf-tl-1..3*.png`。
