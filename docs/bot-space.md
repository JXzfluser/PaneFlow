# Bot 空间：从编排工具到数字员工社会（愿景文档）

> 起点：一次编排运行里的每个 Agent，本质都是一只"跑完即焚"的 Bot。
> 本文回答：如果让它们活下来，PaneFlow 会变成什么——以及怎么一步一步走到那里。

---

## 0. 核心洞察

**Herdr 的 Pane 本来就是常驻的。** 现在的 Agent 之所以"一次性"，只是我们选择在 run 结束时焚毁它们的工作区。把焚毁改成"归队待命"，编排工具就悄然变成了 **Bot 空间**——一个有居民、有领地、有记忆、有法律（约定）、有经济（token 预算）、有政府（编排器）的数字社会。

而这件事的地基已经埋好 80%：

| Bot 要素 | PaneFlow 已有 | 缺口 |
|---|---|---|
| 身份 | 全局角色库（名字/默认模型/前置人格） | 头像/通讯录卡片/履历 |
| 领地 | worktree 隔离 + Space 仓库登记 | 领地还没有"专属感"（临时目录 vs 常驻工位） |
| 记忆 | 终端快照 + OmniRoute memory_fts + `.herdr/artifacts/` | 跨 run 的结构化长期记忆 |
| 技能 | 约定文档注入 + skills/ 目录 | 技能的版本管理与 bot 间传授 |
| 权限 | 审批门禁 + 沙箱白名单 + env 注入 | 细粒度 clearance（按 bot 声明） |
| 生命周期 | 启动闸门/回收/幂等锁 | 常驻化（run 结束不焚）+ 主动唤醒 |

## 1. Bot 解剖学（v1 规格：.bot.yaml）

```yaml
# .bot.yaml —— 一个 bot 的完整定义（可进 git、可分享、可 fork）
id: xiaozhuang                    # 全局唯一
name: 小庄                        # 显示名
avatar: 🏗                        # 通讯录头像
species: claude                   # 底座 agent kind（经模型网关路由）
personality: |
  你是后端开发工程师，严谨、话少、提交的代码必须带测试。
territory:                        # 领地
  repos: [service-order, service-web]
  defaultBranch: feature/auto     # 领地内的活动分支习惯
skills:                           # 注入的技能文件
  - team-conventions.md
  - api-design.md
memory:                           # 记忆配置
  scope: project                  # project | global
  retain: [decisions, artifacts, reviews]   # 记什么
clearance:                        # 权限
  approveLimit: minor             # 可自行放行的最高风险级
  needsHuman: [delete, deploy]    # 必须人闸的操作
budget:                           # 经济
  dailyTokens: 2_000_000
schedule:                         # 日程（可选）
  - cron: "0 9 * * 1-5"          # 工作日早九点
    task: 巡检仓库并汇报异常
```

**关键判断**：`.bot.yaml` 是角色库（roles.json）的超集。角色库给的是"怎么干活"，bot 档案给的是"它是谁、住哪、记得什么、几点上班"。角色库不需要推翻——bot 档案 = 角色 + 领地 + 记忆 + 权限 + 日程。

## 2. 三档天马行空场景

### 🟢 第一档：马上能做（地基已齐，只差组装）

**2.1 Bot 通讯录**
空间视图新增"居民"页：每个 bot 一张卡片（头像/物种/领地/当前状态 idle·working·blocked/本周期 KPI）。点击卡片 = 直达它的 pane（herdr 常驻 TUI 直接围观）。跑完 run 不再焚毁 pane，bot 转为 `idle 待命`——你随时可以点开它直接聊天。

**2.2 Bot 履历与信任评级**
每个 bot 的档案页自动汇总：参与过的 run、验收断言通过率、平均耗时、重试率、被人工驳回次数。跑得越多数据越准 → 下发时 Planner 可以按"信任评级"挑 bot（关键任务派给老资格，练手任务派给新 bot）。

**2.3 Bot 常驻化（run 结束不焚毁）**
run 结束后 workspace 转为该 run 的"营地板间"：bot 们留在各自 pane 里待命。下次同空间下发，Planner 可以优先派已有上下文的 bot（省去重新探索）。空间设置一个"营地板间上限"，超员按 LRU 焚毁最久未用的。

### 🟡 第二档：需要新基建（一两周量级）

**2.4 Bot 间消息总线**
impl bot 完成 → 不只是写 artifact，而是**发消息**给 review bot：`@老王 你审一下我的 diff`。实现上极轻：herdr 的 `agent send-keys` / `pane send-text` 就是现成的 IPC；编排器维护一张"bot 收件箱"表。由此长出真正的**多 bot 协作对话**——你会在两三个终端里看到它们互相讨论方案。

**2.5 事件驱动的 Bot 值班表**
GitHub Issue 打开 → 值班 bot 自动受理（复用受理流水线）；飞书 @bot → 唤醒对应 bot；cron → 巡检 bot 定时巡逻仓库。触发器统一成一张"值班表"（.bot.yaml 的 schedule + 外部事件映射），每个 bot 从"被调用"变成"在上班"。

**2.6 记忆的仪式感**
每个 bot 每次 run 结束写"工作日记"（复用 wrapup 产物 + 快照），归入它的记忆库（OmniRoute memory_fts 现成）。下次唤醒时，记忆库里最近 N 条日记自动注入——bot 会"记得上次你们聊到哪了"。

**2.7 Bot 招聘与解雇**
从模板市场（GitHub 分享的 .bot.yaml）"雇佣"一只新 bot 入驻空间；连续 N 次 KPI 不达标 → 通知你决定是否"解雇"（回收 pane + 归档档案）。空间变成一支可进化的团队。

### 🔴 第三档：纯畅想（写下来是因为它们指明了方向）

**2.8 Bot 竞标机制**：同一个任务放出来，两只 bot 各自提交方案，由评审 bot（或你）打分，胜者执行——把"最优编排"从 Planner 静态决策升级为动态竞标。

**2.9 Bot 梦境模式**：空间空闲时（深夜），低优先级 bot 自主领活：整理自己的记忆、重构自己写过的烂代码、给文档补测试。早上你收到一份"夜间梦境报告"。技术上 = schedule + 空闲检测 + 低速网关档，无新原理。

**2.10 Bot 社会契约**：.bot.yaml 进 git、进 Issue（bot 在自己的 Issue 里汇报）、进 PR（bot 署名提交）——**每个 bot 在 git 历史里留下可追溯的人格**。`git shortlog` 变成团队名录。

**2.11 跨空间人才流动**：A 空间培养的资深 bot 被 B 空间"挖角"（.bot.yaml 导出→导入，记忆可选带走）——空间变成 bot 的"任职经历"。

## 3. 分阶段路线（一步一步）

| 阶段 | 名称 | 交付物 | 依赖 |
|---|---|---|---|
| **B1 落户** | 常驻化 + 通讯录 | `.bot.yaml` 规格；run 结束 bot 转待命；空间"居民"页；bot 履历聚合 | 现有角色库/worktree/快照 |
| **B2 记忆** | 日记与信任 | 工作日记入库；唤醒时注入最近记忆；信任评级进 Planner 选型 | B1 + OmniRoute memory |
| **B3 值班** | 触发矩阵 | 值班表（cron + GitHub 事件 + 飞书 @）；bot 消息总线 | B1 + 通知层（已有出站） |
| **B4 社会** | 生态 | .bot.yaml 市场分享；竞标；梦境模式；预算经济 | B1–B3 + 社区 |

**B1 的工作量评估**：`.bot.yaml` 规格与解析（1 天）＋ run 结束转待命 + 空间上限 LRU（半天）＋ 居民页 UI（1 天）＋ 履历聚合（1 天）。**一周内可见一个活的 bot 空间。**

## 4. 红线与风险（天马行空的边界）

1. **确定性红线不破**：bot 的"自主行为"全部 = 预定义触发器 × 预定义骨架的实例化。bot 可以有性格，但 never 生成任意拓扑。
2. **成本护栏**：常驻 + 日程 = token 消耗放大。预算字段（budget.dailyTokens）必须进 v1，网关侧硬限。
3. **安全边界**：常驻 bot = 常驻可注入终端。clearance 分级 + 审计日志（已有）必须先行；远程暴露模式下每只 bot 的权限独立声明。
4. **焚毁 vs 常驻的资源账**：每只待命 bot 占一个 pane + 内存。营地板间上限 + LRU 焚毁是必需品，不是优化。
5. **不要拟人化过度**：头像和名字是为了信任与可读，不是为了伪装成真人。bot 的每句话都要可追溯到它的身份与依据。

---

## 5. 第一步清单（B1 落户，随时可开工）

1. `.bot.yaml` 规格定义 + 解析器（角色库向后兼容：roles.json 条目可一键"升格"为 bot）
2. 引擎 `burnAfterRun` 开关（默认 false = 常驻待命）+ 营地板间上限 LRU
3. 空间视图「居民」页：bot 卡片（状态/领地/履历入口）+ 直达 pane
4. 履历聚合：run 历史按 bot 聚合 → 信任评级 v0（断言通过率/耗时/驳回数）
5. 通讯录里直接「@它」：选中 bot → 输入框 → 该 bot 的常驻 pane 收到消息（不走 run，纯对话）
