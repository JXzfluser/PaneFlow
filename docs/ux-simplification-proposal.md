# PaneFlow 上手门槛简化建议（界面布局与减负）

> 出发点：**用户要的是"按要求驱动编排"，不是"画 DAG"**。但当前界面把画图放在了主位，把说需求放在了角落。
> 核查方式：逐文件读 `packages/web/src/` 实际实现，证据均给 `文件:行号`。

---

## 0. 结论先行

**核心诊断：PaneFlow 的界面是"给会画 DAG 的人设计的"，而它的能力已经强到"不需要会画 DAG"。**

三条最该做的（按性价比）：

| 优先级 | 动作 | 解决的问题 | 改动量 |
|---|---|---|---|
| **1** | **属性面板分「常用 / 高级」** | 一个 Agent 节点一次展示 ~14 个控件，小白看到就退 | 小（一个组件） |
| **2** | **默认落地页从画布改为「任务」视图** | 打开就往最难的路径走 | 中 |
| **3** | **编排提供「步骤清单」视图（与图形并存）** | 把 DAG 从"你要画的东西"变成"系统给你看的东西" | 中 |

一句话总结：**不是要砍功能，是要改默认。** 所有高级能力都该留着，但**默认不该出现**。

---

## 1. 你的需求被放错了位置

你说「我其实更多的是想能按要求驱动编排」。这个能力**已经存在**，而且做得不错——`DispatchDialog.tsx` 只要 3 个输入：任务描述 + 工作目录 + 关联 Issue（可选）。这就是你要的形态。

问题是它被放在了：

- **编排视图顶栏 12 个控件里的第 3 位**（`OrchestrateView.tsx:70-147`），图标 `🎯 下发任务` 与紧邻的 `☁️ 沉淀`、`⬇️ 拉取`、`⎇ 变量`、`🧹 清空` **完全同级、同样大小、没有视觉权重差异**。
- **默认视图是画布**（`store.ts:117` 默认 `'orchestrate'`）。
- **首次访问自动弹出的指南，第 2 步教的是"从节点右侧圆点拖到下一个节点左侧圆点完成连线，按 Backspace 删除"**（`Guide.tsx:18`）。

**结论：新用户的第一公里，被引导去做最难的那件事。** 而"一句话驱动"这条最短路径，需要用户在 12 个按钮里自己识别出哪个才是入口。

## 2. 实测的错配与缺口

### 2.1 三个错配

| # | 错配 | 证据 |
|---|---|---|
| **M1 入口错位** | 「下发任务」（3 个输入框）埋在编排顶栏第 3 位，与沉淀/拉取/清空同级；默认视图是画布，指南第 2 步教拖线连线 | `OrchestrateView.tsx:76`、`store.ts:117`、`Guide.tsx:18` |
| **M2 模板名是英文 slug** | `tplName()` 把 `builtin-parallel-module-dev` 变成 `parallel module dev`，中文描述只在悬浮 `title` 里。小白看到 7 个英文名：parallel module dev / standard dev flow / risk approval flow / bug fix pipeline / role team review / research compare / issue triage | `Palette.tsx:49`、`Palette.tsx:157-158` |
| **M3 属性面板无主次** | Agent 节点一打开平铺 ~14 个控件：节点名/角色/Agent类型/任务指令/重试/超时/澄清循环×2/环境变量/检查门禁×4/失败策略/放行按键/独立工作目录。**真正必填的只有 2 个**（Agent 类型 + 任务指令） | `PropertyPanel.tsx:112-352` |

### 2.2 五个细节缺口

| # | 缺口 | 证据 | 影响 |
|---|---|---|---|
| D1 | **空间切换器重复出现在两处**（侧栏底部 + 节点库顶部），两处逻辑各写一遍 | `SideNav.tsx:49-60`、`Palette.tsx:110-129` | 同一个概念两个入口，用户不知道以哪个为准 |
| D2 | **空间选择器可能显示陈旧值** | `SideNav.tsx:16`、`Palette.tsx:12` 用 `getSpace()` 读 localStorage，非响应式，切换后不触发重渲染 | 切了空间但下拉框还显示旧值 |
| D3 | **默认工作目录写死** `/tmp/paneflow-workspace` | `App.tsx:53` | 该目录大概率不存在，用户直接点运行会收到「工作目录不存在」——**第一公里就报错** |
| D4 | **用 `window.prompt` / `window.confirm` 做新建空间/复制/重命名/删除** | `Palette.tsx:29-31,52,64,77` | 原生弹窗，无法校验、无法撤销、观感粗糙 |
| D5 | **顶栏有错别字** | `OrchestrateView.tsx:145` 写成 `🕘 迏行中心`（应为「运行中心」） | 细节可信度 |
| D6 | **指南把控制台标签页说成"页"** | `Guide.tsx:21` 说「到『审批』页查看」，实际「审批」「产物汇总」是编排视图**底部控制台的标签页**（`Console.tsx:112-118`） | 新用户会去左侧导航（编/运/设）里找不存在的「审批页」 |

### 2.3 节点库的术语负担

`Palette.tsx:130-138` 把 6 个节点分成三组展示：**基础节点**（开始/结束）、**编排节点**（并行 Fan-out / 汇总 Fan-in）、**核心**（Agent 节点 / 子流水线）。

对小白而言，`Fan-out` / `Fan-in` 是**需要先学图论才能理解的词**。而他真正要表达的是"这几件事同时做"和"等它们都做完"——这是两句中文，不是一个节点名。

## 3. 简化方案

### A. 入口重构：让「说需求」成为主路径（最高优先）

| 编号 | 建议 | 说明 |
|---|---|---|
| A1 | **新增独立主视图「任务」**（与 编 / 运 / 设 并列，建议排第一位） | 打开就是一句话输入框：「你要做什么？」下面挂最近任务卡片。当前 `DispatchDialog` 的内容直接搬过来即可，零新逻辑 |
| A2 | **默认落地页改为「任务」视图** | `store.ts:117` 的默认 `view` 从 `'orchestrate'` 改为 `'tasks'`。画布降级为"高级模式" |
| A3 | **下发后先给"编排预告"，确认再跑** | Planner 选完骨架先展示：「将用『通用交付骨架』：对齐 → 拆解 → **并行实现 ×3** → 汇总 → 验收核对 → 归档，预计 6 步」。用户点确认才执行。**这一步同时解决两个问题：既是"按需求驱动"，又让"编排"以可读的方式被看见**——把复杂度从负担变成透明度 |
| A4 | **任务卡片可展开看编排** | 每张任务卡片底部一个「查看编排」，点开才是画布。想深入的人有入口，不想的人不用看 |

> A3 是本方案里最贴合你产品理念的一条：它把"复杂"转译成"透明"，而不是把复杂藏起来。用户看见的是**可读的步骤计划**，不是一张等着他去画的图。

### B. 视图减法：默认不展示复杂度

| 编号 | 建议 | 说明 |
|---|---|---|
| B1 | **属性面板分两级：「常用」默认展开，「高级设置 ▸」默认折叠** | 常用只留：角色、Agent 类型、任务指令。高级收进：重试/超时/澄清循环/环境变量/检查门禁/失败策略/放行按键/独立工作目录。**改动最小、收益最大的一项** |
| B2 | **模板名中文化** | 给骨架加 `metadata.title`（中文显示名），`Palette` 显示「中文名 + 一句用途」；英文 ID 只在「复制/导出」时露出。至少删掉 `tplName()` 的 slug 转换 |
| B3 | **节点库按"意图"而非"术语"分组** | 把 `Fan-out`/`Fan-in` 改成「并行做几件事」「等全部做完」；或把这两类收进「高级节点 ▸」，默认只留「+ 步骤」 |
| B4 | **空间切换器只保留一处**（建议留侧栏底部） | 删掉 `Palette` 顶部那份 |
| B5 | **空画布引导改写** | 现在是「① 设置工作目录 ② 添加开始→Agent→结束 ③ 拖线连接 ④ 看指南」（`Canvas.tsx:39-42`）——这是**教人画图**。改为两个大按钮：主按钮「描述任务，自动编排」／次按钮「从模板开始」 |
| B6 | **顶栏收纳** | 把 `☁️ 沉淀`、`⬇️ 拉取`、`⎇ 变量`、`🧹 清空` 收进「⋯ 更多」。顶栏只留：模板名 + 保存 + 工作目录 + 运行 |
| B7 | **指南瘦身** | 现在 6 个板块（五步跑通/状态色标/编排语义/黑板交接/模板云端/常见问题），首访自动弹出——是一堵墙。建议首访只给 1 屏：**「描述任务 → 看进度 → 处理审批」三步 + 一句"想画图？点这里"**；其余内容收进「? 指南」的折叠分区 |

### C. 编排双模式：把 DAG 翻译成任务清单（最根本的一条）

同一个 DAG，两种呈现：

```
【步骤清单 · 默认】                        【图形画布 · 高级】
① 对齐需求            ✔ 已完成            现在的 ReactFlow 画布原样保留
② 拆解任务            ✔ 已完成
③ 并行实现 ×3         ● 2/3 进行中
④ 汇总验证            ○ 等待中
⑤ 验收核对            ○ 等待中
⑥ 归档收口            ○ 等待中
```

- **列表视图不损失任何语义**：依赖关系 = 步骤顺序；扇出 = 「×N 并行」；扇入 = 「等全部完成」；条件边 = 「满足条件才执行」。
- **每步一张卡**：做什么 / 用哪个 Agent / 状态 / 产物摘要 / 提示词可展开编辑。
- **小白全程不需要理解"为什么要拖一根线"**。

**这条的本质**：把 DAG 从"**你要画的东西**"变成"**系统给你看的东西**"。而这正好对应你说的那句话——**你说需求，系统生成或选择拓扑，你用清单视角审阅和微调；只有想改结构时才进图形模式。**

### D. 细节修复清单（顺手做掉）

| 编号 | 修复 | 位置 |
|---|---|---|
| D1 | 错别字 `迏行中心` → `运行中心` | `OrchestrateView.tsx:145` |
| D2 | 默认工作目录不再写死；未设置时提示"选择工作目录"或取 Space 的 `rootCwd` | `App.tsx:53` |
| D3 | `window.prompt/confirm` 换成统一小模态 | `Palette.tsx` 多处 |
| D4 | 空间选择器改为响应式（订阅 store 而非 `getSpace()`） | `SideNav.tsx:16`、`Palette.tsx:12` |
| D5 | 指南里的「审批页」改为「底部控制台的『审批』标签」 | `Guide.tsx:21` |

## 4. 建议顺序

| 顺序 | 动作 | 理由 |
|---|---|---|
| 1 | **B1 属性面板分两级** + **D 组细节修复** | 改动最小，立刻降低"看到就退"的比例 |
| 2 | **A1 + A2 任务视图 + 默认落地页** | 直接把你"按需求驱动"的主诉路径变成主路径 |
| 3 | **A3 编排预告确认** | 让编排"被看见"而不是"被画出来"——透明度的关键一步 |
| 4 | **C 步骤清单视图** | 最根本的减负，但改动最大，放在入口理顺之后 |
| 5 | B2/B3/B5/B6/B7 | 文案与信息架构的持续打磨 |

---

## 5. 一句话总结

PaneFlow 现在的问题**不是功能太多，而是默认路径挑错了**。

它已经有能力"你说一句话，它编排好一切"——但界面把用户领到了画布前，递给他一个节点库和一根线。

**该做的是把默认路径换成"说需求"，把画布降级为"想看结构时才打开的详情"。** 这不需要砍任何能力，只需要调整谁在台前、谁在幕后。
