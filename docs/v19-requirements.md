# PaneFlow v19 需求梳理（上手链改造：体验骨架的对标与补齐）

> 输入：一款成熟同类产品的官网/文档逐页拆解（2026-10-09，按其惯例不点名）+ `docs/ux-simplification-proposal.md` 已落地部分的现状核对。
> 性质：评审稿。评审通过前不入远端（家规）。带「待点头」标记的条目不批不动。

## 一、目标（一句话）

**让一个新人在不读任何文档、不碰任何配置页的前提下，60 秒内发出第一条活并看懂第一条结果**——同时把所有机器级强能力原样保留，只是从"首屏货架"挪到"对象详情"和"CLI/机器面"。

不是砍功能，是改默认与陈列（沿用 ux-simplification-proposal 的裁决，这一版把它推到底）。

## 二、对标结论：成熟同类产品到底赢在哪

| 维度 | 参照产品的做法（证据：其官网+文档原文） | PaneFlow 现状（证据：代码/行号） |
|---|---|---|
| 名词负担 | 全站一个 task；空间/团队/编排/跨机全是它的属性 | 首屏可见 5+ 概念：任务/编排/看板/项目/能力/设置（`SideNav.tsx:15-19`） |
| 上手链 | 装→开工作区→Members 看人→New task→挑人→Start，六步零配置 | 说一句话前需先有：项目档案（含 rootCwd）、可用引擎 kind、工作目录须已存在（`RunDialog.tsx` 「须已存在」） |
| 默认安全 | "Plan first" 是默认勾选 | ✅ 已对齐：confirmGate 默认开（`TasksView.tsx:48-50`）；默认落地页=任务（`store.ts:67`） |
| 观察面 | agent 进度日志嵌在任务卡里 | ✅ 部分对齐：timeline 嵌 run 卡；看板统计牌已有（v18-R） |
| 配置陈列 | 无独立设置目的地，配置寄生在成员/任务详情 | ❌ 「能力」「设置」是顶级目的地，纯配置页占了导航的 2/6 |
| 价值叙事 | 首屏一句人话价值（"一个 agent 指挥整队人"式的说法）+ changelog 公开挂页脚 | 首屏「你要做什么？」已是人话 ✅；但差异化护城河（诚实账/机检/指纹）只在 CLI 小字里，应用内无任何一面讲它 |
| 试吃门槛 | 有免安装的网页直达入口 | 本地定位不可照抄；可学的是「第一条任务先于一切配置」 |

**判死一条**：参照产品的"整合感"来自只装饰一个实体；PaneFlow 的"难上手"来自把内部五个实体摆成了五个目的地。

## 三、支柱与需求

### 支柱 A —— 唯一名词：新人只需要「一件活」

**R1 首条任务零前置**
- 现状：发第一条活前，用户实际要完成三件配置（项目档案+rootCwd、agent kind 可用、工作目录存在）；fail-closed 的 400 指路文案已是好的，但出现在"撞墙之后"而不是"铺路之前"。
- 需求：任务页点「开始」时由 server 自动解析：项目=当前空间（无档案→现场用「一句话+一个目录」建最小档案，替代跳向导）；工作目录=项目 rootCwd（不存在→就地给出「创建它」一键，而非报错）；模板=空间默认（无→用出厂最小单步模板，画布留「改计划」入口）。所有解析失败仍 fail-closed，但报错面从红字升级为**带单个修复按钮的指路卡**。
- 可感面：全新 dataDir，浏览器只开任务页 → 输入一句话 → 点开始 → 出现计划预览（无一次手动配置）；CLI 面 `paneflow dispatch "给导出模块加空值兜底"` 不带 `--space` 也能起（server 缺省空间兜底），`status` 输出形状不变。
- 出口判据：新人（或清缓存的自己）从打开 4310 到看见第一条 run 的时间 ≤60 秒、点击 ≤4 次、零阅读。

**R2 术语审查：首屏与卡片只许人话**
- 现状：run 卡/chip 上「graph# · kind= · 档位=」等 harness 行是机器口径（CLI 里它是卖点，在 UI 首屏它是噪音）。
- 需求：Web 面上机器词全部退到 run 详情「技术账」折叠区；卡片层把同一信息翻成人话（「用的是：标准开发流程 · Claude 引擎 · 常规档」）。CLI **一字不改**（机器面保留原口径是家规）。
- 可感面：看板卡片不再出现 `kind=`/`graph#` 字样；点开「技术账」全量在；`paneflow status <runId>` 输出与改动前逐字节相同。
- 出口判据：把看板截图给没读过 README 的人，指不出任何一个需要解释的词。

### 支柱 B —— 人即配置：名册（Members）升为一级面

**R3 「班底」目的地（替代「能力」的顶级位）**
- 现状：一个人能不能干活，信息散在三处——设置·环境（引擎装没装）、设置·网关+模型、设置·角色库（岗位装备）；「能力」目的地是注册表镜子，讲条目不讲"谁在"。
- 需求：新增/改铸一个「班底」视图：每枚成员卡 = 岗位×引擎×模型的解析结果，读数直读既有 API（`/api/health` 的 agentsInstalled、`/api/gateway`、`/api/roles`、team 名册）——**零新判据，只是换陈列**。卡上只回答三问：他在不在（引擎可用+模型可对话）／他会干什么（装备摘要）／最近干得怎么样（`/api/roles/<id>/profile` 已有账）。
- 可感面：点「班底」→ 一屏看见 3 枚人卡，其中 1 枚灰的写明「Claude CLI 未装：装好即自动点亮」；`paneflow registry list` 与能力页互不吞并（能力面讲条目引用账，班底面讲人）。
- 出口判据：派活用"挑人"完成（见 R4）后，新用户从未打开过「设置」。
- **待点头**：这直接决定「能力」「设置」两个顶级目的地的去留走向（见 R7），先画 IA 图过目再动。

**R4 派活挑人，不挑 kind**
- 现状：任务页/节点属性面板暴露 agentKind 选择器 + 模型/档位是另一层。
- 需求：任务页选择器从（隐含的）kind 下拉改为「谁来干」：名单=班底名册解析出的可用成员；背后把 kind/model/gatewayProfile 三元组按成员解析注入（server 已有四级 kind 解析，复用）；「换个别人干/自己指定引擎」留在详情折叠里。
- 可感面：任务页输入框下方出现「由：小规（规划岗·Claude·免费档）▾」；换人只动一枚选择器，全程不出现 "agentKind" 字样。CLI 的 `--arm/model` 语义不变。
- 出口判据：R1 的 60 秒路径里，引擎与模型两次决策都发生在"挑人"这一次点击内。

### 支柱 C —— 诚实账卖成价值：验收凭据

**R5 一单一张「验收凭据」**
- 现状：机检账/产物架/人等分/副作用账/打回账——全套护城河读数在 `GET /api/runs/<id>` 里躺着，消费面是 CLI 小字与详情页的散点。
- 需求：run 收口后详情页顶部一张凭据卡（人话+数字，全部字段读自既有响应，零新落册）：「机检 3/3 实跑全过 · 产物 2 件已上架（sha 可点验）· 全程你等待 4.2 分 · 外部动作：建单 #12、已推送 · 被打回 0 次」；缺键的条目明说「没走到这一步」而不是省略（诚实边界与 CLI 同款）。
- 可感面：给一条真实完成的单，凭据卡能替代一段"为什么信这条绿"的口头解释；点每个数字跳到对应原始账。
- 出口判据：向用户解释「PaneFlow 的绿不是假绿」时，只需指这一张卡。

**R6 迭代叙事面（changelog）**
- 现状：107 枚在飞提交、22 版演进，应用内零叙事；对外信任面（changelog 公开）缺席。
- 需求：设置/关于页加一枚「更新记录」：数据源=随 release 打包的 `CHANGELOG.md`（server 静态读一个文件，不直读 git、不破 R4 铁律），按版本倒序、每条一句人话。仓库侧立规矩：每次合并批次收尾时补一条 changelog（与 commit 规范同批执行）。
- 可感面：应用内「关于」→ 版本号下是最近 5 个版本各一句「这版让你能…」；`cat CHANGELOG.md` 与页面同源。
- 出口判据：新用户 30 秒能说出这产品最近三个版本各干了什么。

### 支柱 D —— 配置寄生于对象：目的地退役

**R7 「能力」「设置」从顶级目的地退役（待点头，本轮最大 IA 手术）**
- 现状：导航 6 席中 2 席是纯配置货架（能力/设置），新人第一眼看到的是"概念货架"而不是"活人活事"。
- 需求（方案，非终稿）：
  - 设置内容按宿主拆走：环境+网关+模型 → 班底成员详情的「他的工具」区 + 一处全局「高级设置」抽屉；GitHub 凭据/通道 → 项目详情与运行设置的就近处；wiki 沉淀 → 项目详情的「知识」区。
  - 「能力」页保留但入口降级为高级抽屉的一枚（CLI/机检口径完全不动——它是 R2/R4 判据的账本，退役的只是导航席位）。
  - 导航终态：任务 / 班底 / 看板 / 项目（四席全是名词性"地方"，零配置页）。
- 可感面：`/api` 无变化；侧栏少两席；原「设置」里每张卡在新位置可找到（对照清单附验收脚本）。
- 出口判据：全量回归绿 + 「60 秒首单」路径不途经任何名为设置/能力的页面。
- **待点头**：① 导航终态四席方案；② 「能力」降级是否保留 URL 直达；③ 手术分批还是一次到位。

### 支柱 E —— 进度嵌在卡里（已有方向，补出口判据）

**R8 看板卡 live 状态不跳页**
- 现状：timeline 已嵌 run 卡；看板统计牌已有。
- 需求：看板列内卡片直接渲染 mini 时间线最后 3 行 + 当前在跑节点的一句话（数据来自既有 `/events`，节流即可）；审批门的批/驳按钮就在卡上（审阅队列已有，核对窄屏路径）。
- 可感面：手机上（配合 v18-R1 远程配对）从推送点开看板，一条卡在列里就能看清"卡在哪一步、为什么"并就地批门。
- 出口判据：观察一单全程 + 批两道门，零次进入详情页。

## 四、负面清单（本轮明确不做）

- ❌ 云托管/多租户/账号体系（本地优先不动摇，「免安装网页直达」不照抄）
- ❌ Web 版脱离 server 的假 demo 模式
- ❌ 砍画布/砍 DAG（编排是差异化本体，退役的是它出现在新手路径上）
- ❌ 为 UI 陈列新增任何 server 判据或落册（R3/R5 一律纯读既有字段）
- ❌ 改 CLI 输出口径（R2 的人话化只发生在 Web 面；机器面逐字节冻结）

## 五、里程碑与顺序

| 里程碑 | 范围 | 依赖 | 出口判据 |
|---|---|---|---|
| v19-α 首条路 | R1 + R2 | 无 | 全新 dataDir 60 秒首单；看板截图外人测 |
| v19-β 人与凭据 | R3 + R4 + R5 + R6 + R8 | R1/R2 先合 | 「从未打开设置」新用户测；凭据卡替代口头解释 |
| v19-γ IA 手术 | R7 | β 全绿 + 三点点头 | 四席导航 + 对照清单验收 |

**执行铁律不破**：审批门必须人批；一切陈列数据只读 API 返回字段（R4 铁律）；fail-closed 宁拒不错放。

## 六、待点头清单（不批不动）

1. R7 的三点（导航终态/能力页 URL 直达/分批策略）。
2. R3 铸「班底」为顶级目的地 = 事实上用"人"的隐喻取代"注册中心"对非机器用户说话——方向性裁决。
3. R5 凭据卡的「缺键明说不省略」会让卡片有时显得残缺——接受残缺换诚实，还是绿单优先观感？
