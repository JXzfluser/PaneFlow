# PaneFlow 设计稿 v1.0 —— 全功能界面设计规范

> 2026-09-14 · 本文是全部页面 UI/UX 的**单一事实源**：设计原则、设计令牌、六个视图的信息架构与交互规格、组件库清单、可访问性基线。实现以本文为准；改设计先改本文。
> 适用范围：`packages/web`（22 个组件、6 个主视图）。当前实现已对齐本文 v1.0 基线，后续迭代在此版本号上递增。

---

## 一、设计原则（五条，冲突时按序裁决）

1. **任务优先于导航**——用户来 PaneFlow 是为了"下发一个任务并拿到交付"，不是为了逛功能。每个视图的首屏都回答"我现在能做什么"，而不是"我有哪些功能"。
2. **状态永远可见**——多 Agent 并行是黑盒操作。任何异步过程（run/blocked/子流水线）必须有实时、可回溯的状态呈现；状态颜色只是冗余通道，文字才是主通道。
3. **确定性可见**——AI 只选模板不画拓扑（红线 D3）。UI 要把"将要发生什么"在执行前展示（编排预告、Dry-Run），执行后可回放（时间线、审计报告）。
4. **简洁是减法**——每屏一个主操作（唯一 primary 按钮）；高级能力默认折叠；配置按"能力接入/系统级"归位到注册中心与设置页，绝不重复出现。
5. **纸感工程风**——暖白纸底、衬线标题、等宽徽标：专业工具的可信气质，拒绝营销页的渐变与发光。

## 二、设计令牌（Design Tokens · 已实现于 styles.css）

### 2.1 字体（三族，各司其职）

| 令牌 | 字体栈 | 用途 |
|---|---|---|
| `--font-display` | Noto Serif SC / Songti SC / Georgia | 品牌、视图标题、卡片标题、审批卡——"书"的气质 |
| `--font-body` | PingFang SC / Helvetica Neue | 正文、按钮、表单——可读性优先 |
| `--font-mono` | JetBrains Mono / SF Mono | ID、时间戳、状态徽标、路径、代码——工程精确感 |

规则：标题层级用 display；任何会变化的数字（耗时/计数/ID）用 mono + `tabular-nums`；正文永远 body。

### 2.2 色彩（双主题，语义令牌）

亮色（默认）：暖白纸 `#faf8f3` 底 + 细网格纹理 + 墨蓝主色 `#2b5fc7`。
暗色（夜读）：暖墨 `#15130e` 底，同色相家族，避免冷灰。

| 语义 | 令牌 | 用途 |
|---|---|---|
| 品牌动作 | `--accent` | 运行按钮、选中态、链接、页签高亮 |
| 成功/进行/失败 | `--ok / --warn / --err` | 节点状态条、徽标——只作冗余通道，文字为主 |
| 层级面 | `--panel / --panel-2 / --sunken` | 卡片 / 输入底 / 代码块 |
| 结构线 | `--border` | 分隔与状态边——深度优先用投影（见 2.4） |

规则：状态色不单独承载语义（必须配文字）；中性色永远向品牌色相倾斜；纯黑/纯白不出现。

### 2.3 圆角、投影、间距

- **同心圆角**：外半径 = 内半径 + padding。卡片 10px → 内部输入 6px；徽标 4px。
- **投影表**：卡片 `0 1px 2px rgba(44,41,33,0.04)`；悬停卡 `0 1px 3px …0.06`；选中卡加 `0 0 0 1px accent` + `0 2px 6px …0.1`。边框只表达结构（分隔/选中），不表达深度。
- **间距阶**：4 基准。组内 8px、组间 16px+、卡片内 14–20px、视图边距 16–20px。
- **按压反馈**：主按钮 `scale(0.96)`，150ms。
- **主题切换**：kill-style + 两帧恢复（已实现），杜绝全页过渡闪变。

### 2.4 动效

- 交互态变化用 CSS transition（可打断），150ms 内，只过渡 `opacity/color/scale`。
- 入场动画仅用于不频繁的弹层/卡片，分语义块 stagger ~100ms；高频列表不加。
- `prefers-reduced-motion` 守卫已全局实现。
- 图标状态切换：opacity 0→1、scale 0.25→1、blur 4px→0。

## 三、信息架构（六视图 + 全局框架）

```
┌──┬──────────────────────────────────────────────┐
│☐ │ 顶条：品牌 · 眉标（当前视图）· 视图级主操作 · 主题/指南 │ 46px
│任│──────────────────────────────────────────────┤
│编│                                              │
│运│               视 图 区                        │
│项│                                              │
│注│  底部控制台（编排视图独有，可折叠/拖高）          │
│设│                                              │
└──┴──────────────────────────────────────────────┘
```

**左侧 56px 导航**（上→下）：任务、编排、运行、项目、注册、设置；底部空间切换器。
**顶条**：左侧品牌 + 眉标徽标（`ORCHESTRATE · 编排画布` 式 mono 蓝框）；右侧全局项（主题 ☀/🌙、? 指南）。
**职责边界**：编排=画一个流程 / 任务=说一句话（智能下发）/ 运行=看进度与产物 / 项目=空间与档案 / 注册=能力登记+配置聚合 / 设置=系统级（环境/角色/外观）。

## 四、六视图规格

### 4.1 任务（TasksView · 智能下发入口）——产品的"门面"

**首屏回答**：说一句话，就能开工。
- 三步卡（①说一句 ②确认 ③开跑）横排解释流程，下方大输入框；
- 「扩写成完整需求」「深档（两稿择优）」两个增强动作以 ghost 按钮呈现；
- 主操作唯一：右下 primary「开始：先给我看计划再跑」；
- 高级选项（工作目录/Issue/编排排）折叠在 `▸ 高级选项`；
- 空态引导：没有班底时显示「一键装填首发五连」。

### 4.2 编排（OrchestrateView · 画布）

**五分区**：模板库(左 224px) | 画布(flex) | 属性面板(右 300px) | 底部控制台(240px 可折叠拖高)。
- 左面板：模板列表（hover 出 ⧉✎⤓🗑 操作条）+ 任务式引导卡（模型/技能/规则/仓库）+ 扫描登记入口；
- 画布：纸底网格、节点白卡衬线标题 + mono 元信息、状态只走状态条与徽标；
- 属性面板：按选中对象切换（节点=按类型渲染字段组 / 连线=条件边编辑）；checks、expand、approveKeys 等高级字段全 UI 化；
- 控制台四页签：运行日志（tabular 时间戳）/ 审批（⛔计数）/ 终端预览（实时+历史回放）/ 产物汇总；
- 顶条：模板名+保存 | 🎯下发任务+⎇变量 | 目录+运行 | 🕘运行中心。
- **主操作唯一**：「▶ 运行」蓝色 primary；停止是红色 danger 仅在 running 态出现。

### 4.3 运行（RunsCenter · 运行中心）

- 顶部状态条：N 运行中 · M 待审批 · 历史 · 🔔 通知开关；
- run 卡片：`#issue 标题`（衬线）+ 状态徽标 + 耗时 + 进度条（done/total）+ ⤓导出/📦归档/↗打开/⏹停止；
- 阻塞节点在卡片上直接列出（不进详情也能看到该处理什么）；
- 空态：一句话 + 指路「编排」；
- 子运行进度实时镜像在父卡片（`子运行 xxx（模板 …）：3/6 节点`）。

### 4.4 项目（ProjectsView · 空间管理）

- 项目卡：名称/建档时间/一句话描述/主仓状态徽标（已配/未配）/班底计数；
- 卡片动作：切换为当前 · 编辑档案；当前项目蓝框高亮 + 「当前在使用」徽标；
- 顶部主操作：🔍发现环境并登记 · ＋新建项目；
- 档案编辑抽屉：主仓根（三入口：最近/浏览/拖拽）、约定文档勾选、仓库勾选、技能勾选。

### 4.5 注册（RegistryView · 能力登记 + 配置聚合）

- 顶部双页签：**能力清单** / **配置聚合**；
- 能力清单首屏：「我想……」任务式引导（接入模型/登记技能/登记规则/登记仓库四卡，点击直达表单）+ 扫描登记（输入目录 → E1 探测 → 勾选预览 → E2 一键入库）；
- 下方按类别分组的只读表：mono 名称 + 引用账徽标 + 来源（出厂/登记）+ 详情；现算类（引擎/节点类型/机检/角色/模板）明示"镜像，不在此登记"；
- 配置聚合：模型网关 / GitHub 凭据 / 出站通道三卡并排（从设置页迁移至此，设置页留跳转指引）。

### 4.6 设置（SettingsView · 系统级）

- 左侧小节导航（运行底座/环境/模型网关/GitHub 凭据/规约与复利/角色库/知识沉淀/出站通道——已迁项留跳转指引）；
- 每节一张卡：标题（display）+ 说明（hint）+ 表单 + 动作；
- 角色库：卡片网格（头像/名称/默认 Agent/前置提示/已部署项目数）；
- 原则：这里是"系统怎么跑"，不是"能力有哪些"。

## 五、组件库清单（复用规则）

| 组件 | 用途 | 复用点 |
|---|---|---|
| `settings-card` | 一节配置的容器：display 标题 + hint + 表单 | 设置/注册/项目档案 |
| 状态徽标（badge done/working/blocked/failed） | 一切状态 | 节点/运行卡/审批 |
| 眉标徽标（view-eyebrow） | 顶条当前视图 | 全局 |
| 引导卡（reg-guide-item） | 任务式入口 | 注册中心；任务视图三步卡同语言 |
| ApprovalCard | 审批人闸：终端快照+放行/终止/补充 | 控制台/运行中心（同语言） |
| RunDialog / DispatchDialog | 运行参数表单（按 variables 声明生成） | 编排/任务 |
| EnvWizard | 零环境三步引导 | 首访自动弹出 |
| 空态模式 | 一句话 + 指路按钮（主 primary 或链接） | 所有列表视图 |

**表单规范**：label 永远显式绑定；必填红星 `*`；错误 `aria-invalid` + 提焦第一个错字段；远程模式下输入 16px 防缩放。

**图标按钮规范**：`title` 与 `aria-label` 成对出现（已批量修复）；hit area ≥24px；一个图标库（Icon 组件）+ `currentColor`。

## 六、可访问性基线（已达标项 + 持续要求）

- 全键盘可达：页签/表单/审批卡均可 Tab 到达，Esc 收起弹层；
- `:focus-visible` 双色环（light/dark 各自验证）；
- 状态三通道：色 + 文字 + 位置；
- `prefers-reduced-motion` 全局守卫；
- 动态内容：审批请求进控制台 `role=log` 区；通知含文字冗余。
