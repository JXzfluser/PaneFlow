# PaneFlow 迭代 v7 需求文档（从「证得实」到「天天用」）

> v0.1 草案（2026-09-18）。上游依据：v6 需求文档（附实施状态表）、全功能面盘点（本文件内 file:line 证据）、Genspark 机制层深勘（2026-09 二次）。
> **本迭代受 Gate 0 裁决门控**：A 组无条件先行；B 组仅在 `docs/gate0-verdict.md` 判 Q1=是 后启动。裁决未落地前，本文档只做计划，不动工。

## 一、目标：v7 到底在干什么

### 1.1 目标锚定（先钉死，再看需求）

| 层 | 内容 | 变化 |
|---|---|---|
| **北极星（项目级）** | AI 劳动的信任层——「AI 干的活能不能信」：规格/隔离/验证/存证/问责五原语 | 不变 |
| **阶段目标** | Gate 0 回答「这台机器对我的真实工作是否可信、可重复、有用」（v6） | 由 v6 交付裁决 |
| **本迭代目标（v7）** | 若裁决为是：把**被证明能用的机器变成我愿意天天用的工作台**——数据不出错、成本看得见、成功可沉淀、上下文不重付。若裁决为否：只做 §3.A 加固包（它们是任何形态下的正确性问题），其余全部作废 | 唯一任务 |

### 1.2 一句话读法

v6 证明「一次跑得通」；v7 回答「日常敢不敢把活放上来」。所有需求只服务四种日常摩擦的消除：**派不了活（输入）、不敢放活（数据可信）、干完看不懂（呈现与账）、每次重头说（上下文与资产）**。Genspark 的对照价值在 v6 已被验证，v7 借它四个机制（§2.1），且刻意抄它的**反面**（成本与审批透明）。

### 1.3 与 Gate 0 / bot-space 愿景的关系

- Gate 0 三问（Q1 场景价值 / Q2 执行层方向 / Q3 成本可核算）→ 决定 B 组是否开工，Q2 结论决定 ProcessOps 是否立项（v7 不做 ProcessOps，只留钩子）。
- bot-space v2（`docs/bot-space.md`）的 B1「常驻+通讯录」是本迭代唯一的向愿景辐射项——它的动机已被 Genspark 侧独立印证：**重启税**（每次新会话重交上下文，业界测得约 30 分钟/天）是 agent 产品最贵的隐性成本，而 PaneFlow 的黑板/产物/角色地基已经付了 80% 的成本（见 §3.D1）。

## 二、四根支柱与需求映射

```
目标：日常可信工作台（Q1=是 前提下展开）
 ├─ 支柱一 派得了活 —— 真实任务进得来、失败接得回           → A5, B2
 ├─ 支柱二 放得心 —— 配置/产物/记录不出错，引擎坑填平        → A1, A2, A4, B1
 ├─ 支柱三 看得清 —— 过程分层可读、账目实时、护栏可预期       → A3, B3, B5
 ├─ 支柱四 留得下 —— 一次 run 变复利资产，上下文不重付        → B4, D1
 └─ 地基扫尾                                              → E
```

批次说明：A 组五项**跨支柱**，是「不赌裁决」的无条件加固包（裁决为否也是正确性问题）；B/D 组按支柱展开，仅 Q1=是 后开工。

### 2.1 Genspark 机制深勘（第二轮，只留可迁的）

| 机制 | Genspark 怎么做 | 转译到 PaneFlow | 判定 |
|---|---|---|---|
| Skill 即资产 | 对话生成 Skill、可介入迭代、一键复用 | 成功 run 反向沉淀为「模板+断言+成本画像」的可版本化 skill | **真抄**（B4） |
| 持久工作区 | 按主题工作区，文件/上下文常驻 | Bot B1 常驻+履历，跨 run 复用黑板 | **真抄**（D1） |
| 审批三态护栏 | per-tool always-allow/require/deny，只拦写不拦读 | manual check 升级为按「能力×对象」档位预配置 | **真抄，成本低**（B5） |
| 成本透明 | credits 不滚存/失败照扣/费率不公开/一天烧穿 | **抄反面**：事前预估、预算硬顶、到顶优雅暂停留中间产物、失败 run 不计账 | **真抄反面**（B5） |
| 交付物回到真工具 | Office 插件字节级 round-trip | 不造编辑器；只把「产物可被本地真工具原样打开、未触碰部分不变」立为验收断言元语 | 立约不实现（B4 顺带） |
| 结果优先节奏 | 暗箱但快，交付物先给 | 保留直播差异化，但呈现分层：摘要→时间线→原始 | B3 |
| Cloud Computer/打电话/公网发布/SSO/积分制 | 云端订阅产品形态 | 无单机对应物 | **不迁** |

口碑负面→刻意避雷（评测源：lindy.ai / presentations.ai / zhe.ink / donews，Trustpilot 口径矛盾处未采信）：不发明积分单位；交付物宁少而准（注水正是 Genspark 被骂最狠处）；编排层不加串行延迟；定价/能力/消耗全程可见。

## 三、需求详述

### 批次 A · 无条件加固包（裁决前即可做，~2.5 天）

**A1 · 设置页丢字段修复（saveProfile 真 bug）【P0】**
证据：`SettingsView.tsx:469-485` 只 PUT `rootCwd+description`，勾选的 `conventionFiles/skills/repos` 前端丢弃；而引擎运行期读的正是 `profile.conventionFiles`（`engine.ts:1193`）→ **约定注入在 UI 上配了等于没配**。这是静默丢用户配置，比 G9 更隐蔽（G9 已被 R2 修复）。
需求：saveProfile 全字段回写 + `spaces` PUT 端点白名单核对 + 一条「保存后重读一致」的回归测试。
验收：勾选 AGENTS.md → 保存 → 重启服务 → 档案里还在。

**A2 · 归档可出（数据只进不出的账）【P1】**
证据：归档按钮已接（`RunsCenter.tsx:150-162`），但 `Store.listArchivedRuns`（`orchestrate/store.ts:176`）零调用者；无反归档、无删除。归档 = 数据黑洞。
需求：归档列表入口（运行中心次级页签）+ 反归档 + 单条真删除（含产物目录联动提示）。纯前端+两三个端点，不动引擎。

**A3 · 成本可见（R6b 的最小身）【P1】**
证据：`run.cost` 后端已全量计算（`engine.ts:408-436`，v6-R6a 合入），前端**零引用**。数据在库里睡觉。
需求：运行卡片与详情加一格「时长/重试/tokens(或 unknown)」；报告区块留到 B 组。这是 v6 R6b 的展示子集，提前做是因为成本格是「日常敢用」的心理门槛——不看账永远不敢点下发。

**A4 · 模板沉淀凭据合一【P2】**
证据：沉淀用 env 的 `PF_GITHUB_TOKEN`（`github-sync.ts:26-36`），设置页存的 PAT 在 dataDir（`github-cred.ts`）——两套凭据，UI 配好仍提示「未启用」（`OrchestrateView.tsx:85-88`）。
需求：sync 读取凭据回退链 env → dataDir PAT；错误文案指向设置页。

**A5 · resume 接线【P2】**
证据：断点续跑引擎已实现（`engine.ts:237-259`）、API 已开（`http.ts:566-574`），前端无入口（`web/src/api.ts` 无方法）。R6.5 的能力用户不可达。
需求：失败 run 卡片加「从断点续跑」+ 确认弹窗（说明继承哪些 done 节点）。

### 批次 B · 裁决依赖组（仅 Q1=是 后开工）

**B1 · G10 黑板别名聚合（引擎唯一改动）【P0，Gate 0 若暴露则升级为 A 组】**
证据：expand 克隆以 `impl__1` 为黑板键（`engine.ts:1085-1101`），下游 `{{impl.artifact.*}}` 解析不到（`:1390-1406`）——9 号骨架靠 verify 直读文件绕开，但这是**每个未来多分支骨架都要再绕一遍的坑**。
需求：克隆完成后按模板节点名聚合别名（数组 + 常用字段合并策略先只定 `summary` 拼接），旧引用行为不变；单测 + 用 9 号骨架的 verify 改回引用式作活体证明。
风险：引擎改动，回归窗必须覆盖 serial/fanout/嵌套三形态。

**B2 · 骨架输入面补全（7/9 无 variables）【P1】**
证据：9 个内置模板仅 2 个声明 `variables`（`builtin-templates.ts:397,474`）。v6 曾以「服务陌生人目标」砍掉；v7 语境变了——**天天用就得天天填真输入**，无变量的骨架只能跑演示。
需求：逐骨架审输入点（bug 链接/仓库/批次清单/审查范围…）声明变量 + RunDialog 必填校验 + 模板测试的变量引用断言已备（`builtin-templates.test.ts` 第三条）。

**B3 · 交付物货架：摘要→时间线→原始三层可读【P1，v6-R5 的替代性收缩】**
证据：Console 已有五页签（`Console.tsx:114-172`），但「日志」页签是原始滚动的 2s 轮询（`:77-96`）；各节点 `artifact.summary` 已存在却只在产物 JSON 里，没有「打开先看什么」的层。
需求：运行详情首屏加「交付货架」区块：各节点 summary 卡片（结论先行）→ 点开进时间线 → 再进原始终端。R5 的自包含 HTML 报告降为可砍项（单人工具里页面即报告，导出走已有 ⤓）。Genspark 机制：结果优先节奏；差异化：它的暗箱我们不抄。

**B4 · Skill 化沉淀：成功 run → 可复用资产【P1，v7 的招牌】**
Genspark 印证「Skill 是复利资产」。PaneFlow 已有半条腿（GitHub 模板沉淀），缺的是把**一次成功 run 的完整上下文**打包：graph + 实填变量值 + 各节点断言结果 + cost 画像，一键存为带出处的「技能卡」，下次从技能卡直接派活（与「智能下发」互为反向：下发从一句话到骨架，技能卡从成功 run 到一句话+骨架）。交付物「可被真工具原样打开」作为断言元语在此引入（不造编辑器，只立契约）。
验收：从 Gate 0 绿 run 沉淀一张技能卡，隔日复用成功。

**B5 · 双护栏：预算硬顶 + 审批档位【P2】**
- 预算：run 级 `maxWallMs/maxTokens(有报才计)` 软顶，到顶**优雅暂停**（保留中间产物 + 标 paused-budgeted），杜绝「一条命令烧穿」的 Genspark 式事故；失败 run 的 attempt 不计入账（Manus 退积分机制的本地化）。
- 审批：manual check 从逐次弹窗升级为角色/节点级三态（always-allow / require / deny），默认只拦「写能力」（命令执行、git 提交、远程调用），纯读放行——照抄 Lindy 的 per-tool 护栏。
优先级 P2 原因：确认窗+blocked 环已兜住最坏情况，此项是摩擦消除不是正确性。

### 批次 D · 辐射项（北极星方向唯一落子）

**D1 · Bot B1 最小身：常驻 + 通讯录【P2，B4 完成后剩余带宽全投这里】**
bot-space v2 的五项落户清单原样有效（角色扩展字段/常驻开关/居民页/唤醒输入/履历聚合 v0，`docs/bot-space.md:86-93`）。v7 只取前四项中的**常驻+通讯录**，履历聚合顺延。
动机已被 Genspark 侧独立验证：重启税（每次会话重交上下文）是 agent 日常化的头号隐形成本；我们的 artifacts/角色库/唤醒端点已付了 80% 地基（bot-space 事实基线表）。
红线：默认 `persistent:false`（维持现状）；远程模式下常驻自动降级焚毁（bot-space §6 评审点 2 采纳）。

### 批次 E · 地基扫尾【P2，见缝插针】

`.tmp-*` 调试脚本清理；`AGENT_KINDS`（`http.ts:45-63`）与 env-check 的 17 种对齐（现缺 gemini 等）；`/api/fs/read`、`notify/settings` 两个零调用端点删除或接线；终端预览轮询改 WS 事件驱动（P5）；`PF_RECONCILE_MS` 坑处置（reconciler 死代码二选一：接线带守卫或删——裁决前按 v6 §七 挂起）。

## 四、执行序

```
现在（裁决前）   A1 → A2/A3 → A4/A5          （~2.5 天，加固不赌裁决）
用户             Gate 0 隔夜 3 连跑 + B 臂 → gate0-verdict.md
Q1=是 ── 关口    B1 → B2 → B3 → B4 → B5 → D1（~8 天，E 组见缝插针）
Q1=否            只保留 A 组；B/D 全部作废；项目按 v6 出口条件降级
```

硬性关口：① B 组任何一项在 verdict 落笔前不写代码；② B1 引擎改动必须过 serial/fanout/嵌套三形态回归；③ D1 在 B4 之后——没有「沉淀」的常驻只是挂着不杀的 pane。

## 五、出口条件

1. A 组无条件交付：A1 有回归测试（配置保存一致性），A2-A5 各自可用。
2. Q1=是 时：B1-B4 全绿 + B4 技能卡隔日复用实证 + D1 常驻跑过一夜不炸（营地上限 LRU 有测试）。
3. 质量底线：测试全绿、typecheck、既有浏览器断言不回退；引擎改动（B1）前后各跑一次 v6 的 9 号骨架 fake-ops e2e 作对照。

## 六、风险

| 风险 | 对策 |
|---|---|
| 裁决前 B 组手痒开工 | §四 关口①写死；B 组代码仓库层面不建分支 |
| B1 引擎改动伤及稳定形态 | 三形态回归 + 别名只增不改（模板节点名旧引用行为不变） |
| 单人带宽：B 组 + D1 ≈ 8-10 天超一周 | 优先级 B1>B4>B3>B2>B5>D1 显式排序，尾部两项可顺延 v8 |
| 「常驻」引入资源/安全新面 | 默认关；上限 LRU；远程模式自动焚毁（bot-space 红线） |
| 技能卡变成第二个模板系统（重复建设） | 技能卡=模板+实填值+断言+成本的**打包视图**，底层存储复用 graphs，不新造一套 |

## 七、不做清单（本迭代明确拒绝）

ProcessOps 执行层迁移（等 Q2 独立裁决）/ R5 式自包含 HTML 报告（被 B3 货架替代）/ 积分或虚拟单位 / 云端形态（远端托管、公网发布、SSO）/ 交付物编辑器（只立「可原样打开」契约）/ 陌生人首跑体验（v6 判决不变）。
